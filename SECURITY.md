## Reporting a Vulnerability

If you discover a security vulnerability, please **do not open a public GitHub Issue or Discussion**, as doing so could expose users before a fix is available.

Instead, please report it privately using the [**Feedback Form**](https://forms.gle/DkHPzEUCHx1NdKjE8).

### Information to Include

To help us triage and investigate efficiently, please include as much detail as possible in your report:

- **Description**: A clear summary of the vulnerability and its potential impact.
- **Reproduction Steps**: Step-by-step instructions or a Proof-of-Concept (PoC) script to reproduce the issue.
- **Affected Components**: Specific versions, commit hashes, or bundled resources affected.
- **Environment Details**: Operating system, runtime environment, and relevant configurations.
- **Supporting Materials**: Logs, screenshots, or stack traces (if applicable).

---

## Response & Resolution Process

We are committed to handling security issues in a timely and transparent manner.

### Accepted Reports

If your report is confirmed:

- We will investigate and develop a patch in a private branch/repository.
- A security release and public advisory will be published in coordination with you.
- You will be publicly credited in our release notes and Security Hall of Fame (unless you prefer to remain anonymous).

### Declined Reports

A report may be closed as invalid or out of scope if it:

- Is not a security vulnerability (e.g., general bug or feature request).
- Cannot be reproduced using the provided steps.
- Affects an unsupported version or operating environment.
- Requires unrealistic, highly privileged, or physical access.
- Is already known or previously reported.

If a report is declined, we will provide a clear explanation for the decision.

---

## Scope

### In-Scope

This policy applies to vulnerabilities in:

- Core **AI Go Teacher** source code
- Official binary releases and packages
- Bundled application resources and configurations

### Out-of-Scope

This policy does **not** cover:

- Third-party dependencies or upstream libraries (please report these directly to the respective maintainers).
- Vulnerabilities resulting from modified, unofficial, or self-compiled builds.
- Issues caused by unsupported, end-of-life, or improperly configured operating systems/environments.
- Social engineering, phishing, or denial-of-service (DoS/DDoS) attacks against project infrastructure.

## 回報安全性漏洞

如果您發現安全性漏洞，請**不要公開建立 GitHub Issue 或 Discussion**，因為這可能會在修復程式發布前，使其他使用者暴露於風險之中。

請改用 [**回饋表單**](https://forms.gle/DkHPzEUCHx1NdKjE8) 私下回報。

### 回報內容

為了協助我們有效率地進行分類與調查，請在回報中盡可能提供以下詳細資訊：

* **問題描述**：清楚說明漏洞內容及其可能造成的影響。
* **重現步驟**：提供逐步操作說明，或可重現問題的 Proof-of-Concept（PoC）腳本。
* **受影響元件**：受影響的特定版本、Commit Hash 或隨附資源。
* **環境資訊**：作業系統、執行環境，以及相關設定。
* **輔助資料**：Log、螢幕截圖或 Stack Trace（如適用）。

## 回應與處理流程

我們致力於及時且透明地處理安全性問題。

### 已接受的回報

如果確認您的回報屬於有效的安全性漏洞：

* 我們將在私有分支或私有 Repository 中進行調查並開發修補程式。
* 我們將與您協調發布安全性更新與公開安全性公告。
* 我們將在 Release Notes 與 Security Hall of Fame 中公開致謝您的貢獻（除非您希望保持匿名）。

### 未接受的回報

如果回報符合以下情況，可能會被判定為無效或超出處理範圍：

* 不屬於安全性漏洞（例如一般 Bug 或功能請求）。
* 無法依照提供的步驟重現問題。
* 影響的是不受支援的版本或作業環境。
* 需要不切實際的條件、高度權限或實體存取權才能利用。
* 該問題已知或先前已有人回報。

如果回報未被接受，我們會提供明確的原因說明。

## 涵蓋範圍

### 涵蓋範圍內

本政策適用於以下項目的安全性漏洞：

* **AI Go Teacher** 核心原始碼
* 官方 Binary 發行版本與套件
* 隨附的應用程式資源與設定

### 不在涵蓋範圍內

本政策**不涵蓋**：

* 第三方相依套件或上游函式庫（請直接向相應的維護者回報）。
* 由修改過的、非官方或自行編譯的版本所產生的漏洞。
* 由不受支援、已終止生命週期（End-of-Life）或設定不當的作業系統／執行環境所造成的問題。
* 針對專案基礎設施的社交工程、網路釣魚（Phishing）或阻斷服務（DoS/DDoS）攻擊。
